# V10.7 极致高分共识升级

## 目标

V10.7 不采用“全局加深”换分数。前测已经确认，把 3–5 空格的极致局面统一从 d4 提到 d5，会明显增加单步耗时；而历史回归也证明搜索深度加一不保证方向排名单调变好。因此本轮只把额外算力投入 **16384 → 32768** 附近最模糊的决策点，并保留 V10.6 的普通路径与大数字安全边界。

## 高分天花板复核

极致模式继续继承 V10.6：普通局面 d4、0–2 空格 d5、满足严格总量证书的 32768 局面高速 d6，65536+ 或不满足证书时安全回退。

V10.7 新增一个非常窄的“天花板复核”入口，只有同时满足以下条件才触发：极致模式、最大数字恰为 16384、空格数为 3–4、主价值核心仍处于 d4，而且 d4 前两名的相对差距不超过 **0.05%**。

触发后，所有合法根方向统一完成 d5。若 d5 与 d4 的第一名相同，采用完整 d5；若 d5 改变第一名，再让所有合法根方向统一完成 d6。只有 d5 与 d6 对新方向形成共识时才覆盖 d4；若 d6 再次改变排名，则判定为深度振荡，恢复原始完整 d4 结果。任何加深失败也恢复 d4，不混用不同深度的根方向分数。

这条规则专门处理已经进入高分后期、但 d4 本身无法明显区分方向的局面。它不是一个短视的合并奖励，也没有更改出生概率、评价权重、风险阈值或 32768 的安全证书。

## 自动玩提速

V10.6 的自动玩会先等待“走棋间隔”，然后才启动下一步搜索。V10.7 改为棋盘生成下一颗随机数字后立即开始下一步 AI 搜索，同时把用户设置的间隔仅作为下一次落子的展示门槛。这样搜索可以与上一手动画和观看间隔重叠。

因此非 0ms 的自动玩稳态由近似“等待 + 搜索”变为“等待/动画与搜索取最大值”。搜索预算、搜索深度和方向评分不因这项 UI 调度优化而下降；0ms 极速模式仍由实际搜索速度决定。

协调器还复用了已经计算出的根棋盘空格数，避免风险入口再次扫描 16 格。这个改动不改变搜索语义。

## V10.6 → V10.7 固定局面对比

复测命令：`npm run benchmark:v107`。环境为 Linux / Node v22.16.0 / 4 个计算 Worker。原始汇总在 `docs/V10_7_BENCHMARK.json`。

### 普通继承语料

202 个继承的可达棋盘全部走普通路径：

| 项目 | 结果 |
|---|---:|
| 天花板复核触发 | 0 / 202 |
| 最终方向不同 | 0 |
| 完成深度不同 | 0 |
| 根方向评分不同 | 0 |
| 主价值搜索节点不同 | 0 |
| V10.6 搜索均值 | 5.14 ms |
| V10.7 搜索均值 | 4.93 ms |
| V10.6 / V10.7 P50 | 3.24 / 3.23 ms |

这一轮普通语料的平均搜索耗时下降约 4.1%，但毫秒级基准容易受调度和 CPU 状态影响，不能把这个比例当作所有机器的固定加速保证。更强的保证是：这 202 个棋盘的方向、深度、根评分和主搜索节点全部一致，V10.7 没有用减深度或减搜索量换速度。

少数总节点计数会因可选风险阶段的运行量不同而波动，但没有造成方向、深度或根评分差异。

### 16384 临界语料

从同一语料构造 100 个 3–4 空格、最大数字 16384 且仍满足高速核心总量证书的临界棋盘：

| 项目 | 结果 |
|---|---:|
| 复核触发 | 24 / 100 |
| 形成深度共识 | 21 |
| d4/d5/d6 振荡并回退 | 3 |
| 最终方向相对 V10.6 改变 | 4 |
| 最终 d4 / d5 / d6 | 79 / 16 / 5 |
| V10.7 触发样本 P50 | 17.17 ms |

4 个改变方向的样本都不是单纯“更深就覆盖”：它们通过了既定的共识规则；另有 3 个样本因为更深层排序不稳定而被拒绝。这里证明的是 **现有评价器下的深度共识质量门槛提高**，不是完整对局得分的统计保证。

临界复核本身会增加这些少数高分回合的原始搜索耗时，这是获得额外信息不可避免的成本；非 0ms 自动玩会尽可能把这部分计算与观看间隔/动画重叠。若要求每一个触发回合的原始搜索毫秒数也绝不增加，就无法同时执行额外 d5/d6 搜索。

## 回归验证

`npm test` 运行 14 个测试组。V10.7 额外覆盖：普通 V10.6 数值等价、16384 深度共识改向、d4/d5/d6 振荡回退、仅极致模式触发，以及自动玩在走棋间隔期间提前启动下一步搜索。

完整测试还继续覆盖规则等价、WASM/native 一致性、MessagePort 协调、风险证明、投影、32768 安全入口、65536+ 回退、撤销/导入/后台状态和连续真实 Worker 运行。

## 关于 50 万分

这个版本把算力放到了更可能限制高分上限的 16384→32768 过渡阶段，并且 32768 之后仍继承 V10.6 的高速 d6，因此它比简单全局加深更适合冲击更高峰值。但 2048 的出生位置与 2/4 随机性会显著影响整局结果，当前没有足够多的 V10.7 完整配对对局可以证明“最高一定达到 50 万”或“平均分必定提高某个百分比”。

因此 V10.7 的可验证承诺是：普通路径不降搜索质量；高分模糊局面获得更严格的 d5/d6 共识复核；不稳定加深自动回退；非极速自动玩减少等待与搜索串行造成的可见延迟。50 万应作为后续完整种子回归的冲刺目标，而不是写死在程序里的保证。

## 复现

```sh
npm run build
npm test
npm run benchmark:v107
```

基线 `tests/fixtures/v10.6/2048-ai.html` 是开始 V10.7 修改前保存的 V10.6 自包含版本，用于固定 A/B；不要用当前构建覆盖它。
