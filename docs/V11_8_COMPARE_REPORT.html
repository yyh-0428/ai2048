三、关键发现

  • V11.6、V11.7(正式)、V11.8 默认神级，逐局结果完全一致（8 个起点全部同分同棋盘）。三者的默认神级就是同一套策略 —— 也就是 V11.6 那套「高分残局共识复核」。V11.7 正式版 README 自己也写明「神级维持 V11.6 原策略」。
  • V11.7(验证候选) 是唯一有变化的神级：均值最高（4770 步 / 32.5 万分，比 V11.6 高约 5%），但方差极大 —— 在 seed-603/623/624/625 明显更强，却在 seed-615/622 崩得厉害（2375 步）。属于「高方差、偶发早死」的候选策略，没有被正式版采纳。
  • V11.8 实验神级（续命仲裁：counterfactual + learnedTrajectory + trajectoryEscape + trajectoryAssetGuard）平均反而略低（4291 步），且单步耗时约 5 倍。它大多时候与原策略一致，但个别起点（seed-615）会退步。
  • V11.9 默认神级出现严重回退：8 局中 6 局在 500 步内死亡，平均仅存活 907 步（约 V11.6 的 1/5），终局分从 ~32 万掉到 ~22 万。

五、V11.9 回退归因

六、结论与建议

1
V11.6 / V11.7(正式) / V11.8
默认神级完全等价：平均存活 4538 步、终局 ~32 万分、单步 ~1.6ms，且最稳（8 局仅 1 局早死）。三者之间任选，性能与棋力都相同。
2
V11.7(验证候选)
均值最高（4770 步 / 32.5 万分）但方差极大，会在部分随机流崩盘。适合研究，不适合当默认。
3
V11.8 实验神级
续命仲裁整体略低于默认（4291 步），且慢约 5 倍，个别起点退步。默认关闭是正确的。
6
V11.9（默认神级）
明显最弱：平均仅 907 步、6/8 早死、慢 6 倍。当前默认配置不建议使用。

给你的直接建议

  • 想要最强又最稳：用 V11.8（或等价的 V11.6 / V11.7 正式版）。V11.8 作为检查点版本，默认神级与 V11.6 完全一致，但工程更干净。
  • V11.9 暂时别用默认神级。若必须用 V11.9，请在 policyOptions 里关闭 lifetimePlanner / viabilityPlanner / reservePlanner，即可恢复到与 V11.6 相同的棋力；但那样也就没有使用 V11.9 的意义了。
  • V11.8 的实验神级（续命仲裁）默认关闭是对的，实测无收益、有回退、还慢。

七、方法与局限

  • 驱动方式：直接抽取各 HTML 内嵌的 coordinator / worker 源码，在 Node worker_threads 中运行（4 worker），与浏览器是同一份逻辑；非浏览器渲染，不含绘制时间。
  • 配对性：每个起点恢复棋盘、分数、累计步数、mulberry32 完整状态，所有版本面对相同方块序列，属严格配对。
  • 样本：8 个真实高分残局（V11.7 的独立集）。这是 V11.7 的开发/验证数据，对 V11.9 属「旧流」；V11.9 自己的新流结论（44 对 2 胜 42 平 0 负）不在此覆盖范围内，两者不矛盾 —— 本报告只说明在这些已知高分残局上各版本的实际表现。
  • 速度：230 棋盘 × 3 轮热缓存，交替顺序；单进程顺序执行。绝对毫秒受机器负载影响，横向对比同批测量内有效。
  • 所有原始数据：docs/V11_8_COMPARE_PLAY*.json、docs/V11_8_COMPARE_LATENCY.json、docs/V11_8_COMPARE_MERGED.json；脚本在 tools/compare-*.cjs。
