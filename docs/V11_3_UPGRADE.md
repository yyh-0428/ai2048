# V11.3 分支合并与神级稳态升级

## 背景

V11.2 是从 V10.6 单文件分支继续发展的“神级”路线；V10.7 则在完整工程中继续保留了 V10.6 的构建链、32768 严格总量证书高速核心、JS TT 单次哈希优化，并新增 16384 临界局面的 d4/d5/d6 共识复核与自动玩搜索/展示重叠。

V11.3 的目标不是继续盲目增加深度，而是先消除分支回归，再把两条已经独立验证过的能力合并到同一个可测试工程。

## 合并原则

1. `rules.js` 继续保持历史冻结，不把神级写入共享规则层。
2. 神级作为 coordinator-only 策略覆盖，旧的 fast / strong / extreme 规则语义不变。
3. 32768 只在严格证书成立时进入 4-bit V102 价值核心；任何可能在搜索视野内产生 65536 的局面继续回退 JS。
4. 16384 共识复核仍只属于 extreme；god 已直接完成 d6，不重复做 d4→d5→d6 流程。
5. 新的评估权重不进入正式版本，直到有配对长程结果支持。

## V11.3 实际变化

### 1. 保留 V11.2 神级

- 空格 <= 7：V102 d6。
- 空格 >= 8：V102 d5，避免请求不会继续展开的无效层。
- `riskH=7`、`riskNodes=360000`、`riskGap=.008`。
- 短期安全证明预算 `49152 nodes / 4 ms`。
- 神级更早进入危险局面复核。

### 2. 恢复 V10.6 的 32768 严格高速核心

V11.2 的单文件修改把 `packValue4` / `valueCoreEligible` 路径移除了，因此 32768 会直接进入 JS compatibility 搜索。

V11.3 恢复：

- rank 15（32768）可精确编码；
- 棋盘总量满足 `mass + 4 * depth < 65536` 时，证明整个搜索视野内不可能产生 rank 16；
- god/extreme 在安全 32768 局面可直接完成 V102 d6；
- 两块 32768、已有 65536、或接近总量边界时继续拒绝高速核心。

### 3. 恢复 V10.6 JS TT 单次哈希

保留 `PROBE_K1 / PROBE_K2` 快照，在 cache lookup 后递归搜索结束时复用相同键写回，避免同一节点做第二遍 16 格哈希。评分、节点与替换语义不变。

### 4. 合并 V10.7 的 16384 共识复核

仅 extreme、最大块 16384、3–4 空格、d4 前两名差距 <= 0.05% 时触发：

- 全根统一 d5；
- d5 与 d4 相同：接受 d5；
- d5 改向：全根统一 d6；
- d5/d6 对新方向一致：接受；
- d4/d5/d6 振荡：恢复完整 d4。

God 已直接 d6，因此不经过这条复核。

### 5. 合并 V10.7 自动玩调度

下一步搜索在随机出生后立即开始；用户设置的走棋间隔只作为展示门槛。非极速模式下搜索可与动画/等待重叠，不降低搜索预算。

## 没有进入正式版的实验方向

V102 的叶子评估仍是行/列可加的局部启发式：空格、同线可合并、单调性与大数字代价。它没有显式表示“两个同级高块跨行/跨列最终能否汇合”的全局结构。

这仍是后续研究重点，但 V11.3 不直接加入高块距离/连接性权重，因为现有 6 个 hard-start 样本不足以证明长期收益。下一阶段应先扩充 8192→16384 与 16384→32768 的配对起点池，再做 evaluator A/B。

## 验证

V10.7 原有 14 组回归全部通过，并新增 V11.3 专项：

- sub-32768 的 God 在固定困难局面上与 V11.2 方向、深度、V102 根评分和节点完全一致；
- 安全 32768 的 God 进入 `wideValueCore` 并完成 d6；
- 两块 32768 / 65536 继续回退 JS；
- God 直接 d6，V10.7 ceiling refinement 仍只作用于 extreme；
- UI 暴露四档模式并默认 God；
- 额外完成 300 步固定种子 God 连续走棋 smoke，无非法方向。
