# V9.2 架构

`src/page.html` 是页面模板，`src/ui.js` 管理棋盘与交互，`src/rules.js` 是纯规则和模式参数。`tools/build.mjs` 把所有源码内嵌为单文件 `2048-ai.html`，无需网络或运行时打包器。

页面拥有棋盘状态、历史、分数、存档和落子权。UI 每次给调度线程发送 `{id, revision, board, strength}`；只有同时匹配当前 id/revision 的结果可以提示或落子。

调度线程 `src/coordinator.js` 拥有一整步搜索的阶段、预算、已完成层、风险结果和候选分数，执行固定顺序的平局处理。它通过 MessagePort 直接调度至多 4 个计算 Worker，不让搜索轮次经过页面回调。

计算线程 `src/worker.js` 负责单一根方向的精确目标深度搜索或一次完整 Survival 分析。每次精确搜索前清 TT，保持根方向独立。普通 WASM 字节与 V9.1 一致，Survival WASM 与配套 C/wasm 文件保持一致。

## 决策顺序

1. UI 对唯一合法方向直接返回；其他局面进入调度线程。
2. 等全部计算线程初始化完成、旧的取消工作排空后开始计时。
3. 根 D4 规范化；若与最近一次同棋盘同模式的完整结果一致，复用结果。
4. 从质量底线开始，同步完整轮次渐进加深。同轮统一剩余预算，按各计算通道内的搜索耗时累加并取最长通道计账（少核的顺序任务也累计）；任何不完整/超时轮次均丢弃。
5. 脆弱局面进入 Survival。Extreme H7 达节点上限后回退 H6。
6. 当风险结果与常规结果冲突且超过门槛，对两个争议候选运行高质量 Verifier。
7. Verifier 必须完整且支持风险候选，才能覆盖最终方向。
8. 将完整结果还原为用户棋盘方向并发送给页面。

## 大数字与 WASM 不可用

只要根或任意移动后棋盘达到 32768，整步所有候选转 JS。任一计算线程初始化 WASM 失败时同样统一切换。JS 用共同 d2 起步，在原有模式兼容预算内渐进加深；必要时全根回 d1。正常 WASM 的质量底线、概率截断、采样和预算不变。

## 取消与显示

取消会递增 id、清理 UI 自动计时器/队列，调度线程丢弃工作状态。已经进入计算线程的同步搜索可在预算内结束，结果因 id 不匹配而被丢弃，健康线程保留供复用。失联/报错或 pagehide 才销毁。

极速模式直接提交棋盘，棋子固定 16 个节点、至多约 25 fps 绘制；指标和状态文字至多约 10 fps。手动及慢速模式使用可取消的独立动画，下一步搜索可与当前动画并行。

搜索耗时从调度线程开始一整步搜索到发出完整结果，不包含初始化、页面收取结果的延迟或走棋间隔。线程仍共享设备 CPU，因此不能保证不同 UI 负载、后台状态或设备温度下的 wall-clock 棋力完全相同。

Worker 内的耗时由 performance.now() 测量，仍包括该线程的 OS 调度延迟，并非硬件 CPU 使用时间。界面展示整步调度历时，实际响应时间还包括消息交付；不可混用这几个指标。
