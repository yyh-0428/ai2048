# V11.4：让 God 的完整 d6 评分拥有最终解释权

## 为什么这一轮先不改评估函数

V11.3 已经把 V10.7 完整工程与 V11.2 神级分支合并稳定。V11.4 的第一步不是继续加特征，而是重新检查“God 的最终方向到底由谁决定”。

V102 的主体是完整根分支 d6 Expectimax。搜索结束后，coordinator 还会执行一个继承自 V10.4 的近似平局规则：若前几名价值分差不超过 0.05%，优先选择即时合并分更高的方向。这个规则在 d4/d5 时能减少小数噪声，但在 God d6 上触发过于频繁。

固定困难起点 #0 的前 1500 步中，V11.3 的 `tieAdjusted` 触发 183 次（12.2%）。其中存在这样的真实局面：

- d6：`down = 1,299,755.5`
- d6：`right = 1,299,484.625`
- 相对差约 0.02084%
- V11.3 因即时合并规则改走 `right`

这不是数值平局，而是浅层合并偏好覆盖了已经完成的 d6 排名。

## 正式改动

### God 的 tie gate 从 0.05% 收窄到 0.005%

- fast / strong / extreme：仍为历史 0.05%，语义不变。
- God：只有原始 d6 前几名相差不超过 0.005% 时，才允许即时合并规则改向。
- Survival、安全证书和 verifier 逻辑不变；它们仍可以在有独立证据时覆盖价值方向。

这个改动的含义不是“永远相信启发式评分”，而是区分两种覆盖：

1. **即时合并 tie-break** 是一层浅规则，只处理真正接近的价值平局；
2. **风险覆盖** 有独立 Survival / verifier 支持，仍保持原来的安全优先级。

## 两个边界样本

### 样本 A：不再覆盖 d6

棋盘：

```text
2     2     8     64
8     4     16    256
2     8     32    512
0     16    128   8192
```

V11.3 在 0.02084% 的分差下从 d6 原始 `down` 改成 `right`。V11.4 不再把它当作平局，保持 `down`。

### 样本 B：真正极近时仍稳定化

棋盘：

```text
2     0     4     64
0     2     32    256
0     0     64    512
4     2     128   8192
```

`right` 与 `up` 的 d6 差距只有约 0.000809%。V11.4 仍允许即时合并规则选择 `up`，因此没有把 tie-break 完全删除。

## 本轮被否掉的实验

### 1. 换位表 2^18 → 2^19：拒绝

扩大 TT 的确略减节点并略提速，但评分 checksum 发生变化。原因是 V102 的缓存是有意的近似缓存：剪枝依赖累计出生概率 `p`，而 TT 键没有包含 `p`；更换碰撞/替换历史会改变近似值。因此它不是纯性能改动，不能未经质量 A/B 就合入。

### 2. 降概率剪枝并真正展开 d7：拒绝

之前所谓“d7 与 d6 树相同”，本质上受 `p < 0.0001` 硬剪枝影响。把 God 的概率门降低后，d7 确实开始展开新树，但在 6 个 hard-start 上节点总量从约 478 万上升到约 1648 万，超过 3 倍；集成实跑明显拖慢困难局面，不适合当前浏览器本地产品。

### 3. d6 内轻微降低概率剪枝：暂不合入

把 cutoff 从 `1e-4` 降到 `7.5e-5`，只增加 d6 的低概率出生分支，成本约增加 20–30%。但：

- 6/6 hard-start 初始根方向没有改变；
- 28 个稠密合成 8192 局面根方向 0/28 改变；
- hard-start #0 前 500 步只有很小的分数差，没有形成可证明的质量优势。

所以暂时保留现有核心。

## 下一阶段

V11.4 后最值得继续研究的不是暴力 d7，而是两条路线：

1. **高阶结构/大块汇合能力**：做成 God-only 的可回退评估实验，并扩大真实 hard-start 池后再 A/B；
2. **小型残局表 / formation planner**：只覆盖特定高分结构，不引入桌面级超大 lookup table，保持单 HTML、本地浏览器可用。

任何实验都继续遵守：旧三档语义冻结、God 改动单独开关、先确定性回归再长程配对。
