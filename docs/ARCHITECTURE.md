# 架构与维护约束

**V11.8 更新：**保留 V11.7 的完整搜索、共识、合并偏好、风险层和兼容保护；新增反事实续命规划、学习型生存谱、模拟终点复核和证据仲裁。所有新决策均有独立布尔开关并纳入缓存键，只在神级读取。默认选择由预先承诺的独立终局验收决定，结论以 V11_8_UPGRADE.md 和 V11_8_RELEASE_DECISION.json 为准。V11_7_* 与更早的报告属于历史证据，不是本轮成绩。

## 项目结构

| 路径 | 用途 |
|---|---|
| `2048-ai.html` | 可离线双击运行的完整发布文件 |
| `src/page.html`、`src/ui.js` | 页面、输入、绘制、自动游戏、存档操作 |
| `src/rules.js`、`src/session.js` | 2048 规则和存档验证 |
| `src/coordinator.js` | 独立调度 Worker；规范化棋盘、分发全部根方向、风险复核、结果缓存 |
| `src/worker.js` | 计算 Worker；内嵌 WASM 与大数字 JS 兼容引擎 |
| `src/counterfactual.js` | 公开棋盘生成虚拟未来，完整配对续命模拟与仲裁门槛 |
| `src/learned-survival.js`、`models/` | 64→32→3 条件生存谱、三模型共识及真实轨迹训练数据 |
| `v102_ai.c/.wasm` | 当前 bitboard Expectimax 核心；保留旧文件名以兼容构建与测试 |
| `survival_v9_1.c/.wasm` | 有限视野生存检查 |
| `tests/`、`archive/` | 回归测试及仍被测试使用的旧样本；不是游戏运行依赖 |
| `tools/` | 无网络构建、测试入口、交替 A/B 基准 |

页面只提交棋盘并接收完整结果；协调器通过 MessagePort 直接调度最多 4 个计算 Worker。减少主线程绘制和消息延迟对搜索调度的影响。

## 计算开销优化

协调器预先建立 8 个逆向坐标表，直接比较变换后的视图，只生成最终胜出的棋盘数组；选择变换的顺序与并列处理和原 `canonicalAI` 完全相同。风险层按相邻格的移动/合并关系计算四方向可动性，避免重复扫描四套行列表。横向或纵向隔空合并已经具备可滑动的邻格，不会漏掉合法方向。

回归把规范化结果及变换编号与原规则逐项比较，并把可动性计数与实际生成合法动作比较，包含原语料、八份残局的全部旋转/反射、全空/全满并列状态和 5,000 个随机大数字棋盘。价值 Worker 消息只保留计算用到的字段；全部合法根仍完整计算，风险任务和 verifier 配置继续完整传递。

## 价值搜索和模式选择

根棋盘先做 D4 规范化，并枚举全部合法方向。轻快固定用价值核心 d3；深入、极致、神级在原棋盘空格数 >2 时用 d4，<=2 时用 d5。神级和极致另有高分近分复核。只有一个合法方向时直接返回，无合法方向时结束。`config` 可以接收同一棋盘的预先枚举根动作，以复用溢出检查；输出配置与 V11.5 相同。

价值核心仍使用 64-bit bitboard、65536 行移动/评价表、90% 2 / 10% 4 出生、所有出生格枚举、概率截断和每次请求隔离的近似转置表，评价权重保持原样。V11.8 新训练的小模型在完整主搜索之后介入，不替代主搜索评分。d5 表示相同核心的额外行动周期，不等同于旧评价器的同名深度或数学精确求解。

旧深入在 <=2 空格时切换旧评价器，在预算内重复加深；V11.6 与极致一样直接完成一次高速核心 d5。所有根分数仍来自完整同深度搜索；这是同一核心的深度保障，不表示两套评价器的同名深度或分数等价。

### 神级的实际出招共识

继承的触发条件仍为最大块 8192/16384、3–4 空格、d4 前二相对差不超过 0.05%。原本只看原始评分第一名，之后的合并偏好可能改写实际推荐。V11.6 仅在原始 d4/d5 第一名相同、实际推荐不同的情况下增加 d6 检查；要求 d5/d6 原始第一名和实际推荐都一致。确认后仍采用完整 d5 分数和原来的 verifier 深度，d6 只作为证据；否则恢复完整 d4。

原策略已经要求的 d6 不会被跳过，也没有扩大全盘加深、改评价权重或缩小合法根方向集合。极致继续使用 V11.5 原策略。

### 风险层

1. 主搜索给出候选，原脆弱性门槛判断是否需要复核。
2. 三态安全证明返回 safe / not-certain / unknown。只有有效 safe 能省掉生存计算；不完整结果不写成反例。
3. 必要时运行 Survival。极致 H7 达节点上限后退 H6。
4. 生存差距达到门槛后，才对主候选与安全候选在原棋盘上做更深独立复核。极致 d4 对应旧核 d5；极致 d5 对应旧核 d6。
5. 常规改方向仍要求独立 verifier 的两个结果都完整且支持安全候选。超时或不支持时保持主结果。

神级有一个严格例外：全部合法根的完整价值分数都等于核心终局底值 `Math.fround(1e-6)`，此时价值结果没有排序信息。只有生存计算完整、每个合法方向概率有限且在 [0,1] 范围、候选合法、总量/视野边界安全时，才能按严格为正的生存概率差选择方向。不可使用部分概率、大数字投影或兼容路径。结果标记为 `terminalRescued`，不能标记成 `verified` 或短期安全证明；H7 中止后的完整 H6 会明确记录实际视野。

复核比较只在同一个复核引擎内部进行，禁止把两套评价器的分数直接比较。

### 大数字

32768 可以进入价值核心的条件是每块均可表示，且根总量加六次最大出生量严格小于 65536；神级/极致在这条有证书的大数字路径使用 d6。边界不满足、已有 65536+ 或 WASM 不可用时，继续用原数字 JS 兼容路径，不解除入口保护。有限视野投影仅用于 Survival；最终常规风险换方向仍需原棋盘 verifier 支持。

## 构建与可复现性

`tools/build.mjs` 在构建时从外部 `v102_ai.wasm` 同步 Worker 内嵌字节，并同步外部 `survival_v9_1.wasm`，校验两份标记后再生成 HTML，防止源码/模块与实际离线页面不一致。

当前环境有 GCC、没有 wasm32 clang。交付 WASM 使用 `tools/extend-core.cjs` 对固定 SHA256 的 V10.4 原模块做确定性特化：只修改 `min(depth,4)` 的两个立即数为 6，不修改算法指令或其余字节。输入散列或指令位置不匹配会拒绝生成；C 源码中的深度上限同步为 6。

已有 GCC `-O3 -ffp-contract=off` 独立核对 256 组 d3/d4/d5/d6 的 float32 评分、节点数及命中数。历史数据保存在 `tests/fixtures/core-d3-d6.json`，本轮回归仍逐项核对这些固定向量。普通 `npm test` 不要求安装编译器。

从 C 重编译时需要带 WebAssembly 目标和链接器的 clang。编译器版本可能改变浮点、优化或模块布局；必须再跑构建、测试和性能基准，不把任意编译器输出宣称为字节相同。内嵌的旧兼容 WASM 来自历史版本，原 C 源码并不完整，这是继承限制。

## 必须保留的约束

- 棋盘值不能因窄位表示而饱和；单次移动不能连锁合并；真实 gain、终局判断和方向变换必须正确。
- 近似 TT 不跨请求、根方向或加深轮污染；完整棋盘相等才允许精确叶缓存命中。
- 不按浅层 Top-2 淘汰其他合法方向；部分轮次不能参与比较。
- 取消、撤销、新游戏、导入后旧结果必须作废。只在 Worker 异常或页面退出时销毁健康线程池。
- 保存有效存档格式、有限安全整数、输入校验和异步导入的竞态保护。
- 基准记录棋盘总量、分数、最大块、步数、低分尾部和延迟。基准时不同时运行其他 CPU 密集任务；不把搜索节点数当实际游戏产量。

## V11.7 实验与缓存隔离

正常神级的真实 profile 仍为 extreme。白名单 policyConsensus、terminalRescue、actualConsensusPromotion、mergePreference、fallbackConsensus 只接收布尔值并纳入结果缓存键；只有神级读取实验覆盖，其余模式忽略。双共识只处理原 policy-only 额外检查失败，不扩大原 d4 触发集或跳过原 d6。无法支持退回 d4 时保留完整 d5 与对应 verifier 深度，并独立标记证据未确认。所有原始评分与概率的部分结果丢弃机制不变。

新20起点与旧8开发样本分目录，保存真实分数/总步数/完整PRNG及出生势能证书。终局日志逐步核对评分方向集合、实际出招、出生位置/值和随机状态；另一脚本从头回放质量与分数及终局。阶段HTML冻结为精确字节复现入口；新测试成绩不使用旧报告。
