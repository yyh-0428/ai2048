# V9.2 页面与 AI 审查

本次基于上传的 V9.1 完整项目修改。视觉判断来自 HTML/CSS 与交互代码审查；当前浏览器安全策略禁止打开本地文件，未取得实际页面截图。没有把模拟 DOM 测试当作真实浏览器验收。

## 界面与体验

原版的米色背景、克制的色彩、清楚的棋盘与分数层次适合继续保留，无须为改版重新设计全部风格。问题主要集中在操作可达性、信息表述和状态一致性。

| 原问题 | 修改 |
|---|---|
| 手机上的 AI 操作区在棋盘下方，可能需要滚动才能暂停 | 固定底部两项操作，预留安全区与页面底部空间 |
| 主要说明堆积 d4 / H7 / TT 等细节 | 默认显示玩法与强度差异，技术说明折叠 |
| 方向分数标为百分比，容易误读为获胜概率 | 改为相对评分并说明含义；并列同分保持同长度 |
| 自动玩中的指标实际上是刚刚执行的决策 | 明确标为“上一步的方向评估” |
| 浅色数字块与次要文字对比不足 | 提高前景色对比；8 数字块由约 2.13:1 提到 5.29:1，次要文字由 4.20:1 提到 4.99:1 |
| 强度选择缺少辅助技术状态 | `aria-pressed`、可见焦点、较大触控区域 |
| 隐藏结束层仅透明，内部按钮仍可被 Tab 聚焦 | 用 `hidden` 真正移出交互树 |
| 棋盘与提示缺少可读信息 | 棋盘可聚焦、每格有行列与值、提示/暂停有节制的读屏播报 |
| 键盘空格会覆盖已聚焦按钮的默认行为 | 尊重按钮、输入框、可编辑区以及组合键 |
| 减少动画偏好只改变 CSS，手动逻辑仍等待 | 同时取消 JavaScript 动画等待 |
| 刷新无法恢复本局 | 本地自动保存，恢复后保持手动/暂停状态 |
| Mac 每次随机端口，浏览器存储归属不同来源 | 固定本地端口；保留文件模式回退 |

## 已修复的状态 BUG

- **旧提示**：手动移动没有使原来的 AI 请求失效。新版本同时检查请求 id 与棋盘 revision。
- **撤销后 AI 不响应**：原 `undo()` 没有清掉 `aiBusy`；新版本统一取消与解锁。
- **新游戏与旧动画竞争**：原动画 timeout / RAF 无取消；新版本保存句柄并校验动画代次。
- **暂停后仍启动一次搜索**：原自动计时器没取消、`askAI('auto')` 未核对自动状态；两处一起修复。
- **过期动画结果**：修改速度、缩放、新游戏或暂停后不再消费旧棋盘结果。
- **唤醒锁泄漏**：结束、离开页面、暂停与新游戏均释放；异步申请完成时再次检查状态。
- **后台动画挂起**：页面隐藏时取消并跳过动画，避免已完成的 AI 结果无限等待被暂停的 RAF；浏览器自身后台限速仍存在。
- **异常后僵住**：计算错误直接送回页面并恢复手动操作，另有失联超时保护。
- **进程 PID 复用**：Mac 停止脚本先检查目标进程来自此项目；服务器退出回收 nc 子进程。

## AI 设计评价

保留高速 WASM Expectimax、根 D4 规范化、独立 TT、阶段深度上限、风险哨兵与 Verifier 的组合有充分的历史理由。直接换更重的主核、强制所有局面加深或只搜浅层前两名都违反了已有反例，不适合本次目标。

更直接的缺陷是页面承担每一轮的调度与计时。原版四个 Worker 即使已经算好，也必须等主线程处理四个回调才能开始下一层；DOM 绘制和动画造成的主线程等待会消耗全局预算。因此页面的负载可以改变完成深度，进而改变最终选择。

V9.2 增加一个仅负责调度的 Worker。页面创建 MessageChannel，把两端交给调度与计算 Worker。每轮搜索、Survival、H7→H6、Verifier 的往返均留在线程之间，页面每步只收到完整结果。计算线程准备完成之后才开始计时，冷启动不再吞掉首次加深预算。共享 CPU / OS 调度与后台限速仍然存在，因此不能声称 UI 与 AI 在物理资源上完全独立。

## 大数字兼容路径

原版有多个可复现问题：

1. 某些移动生成 32768 后使用 JS，而其他根仍使用 WASM，评分尺度不同却直接比较。
2. 原 `analyzeRoot` 在每个精确目标深度请求中又从 1 层算到 d 层，重复前面工作。
3. 初始目标深度超时后没有完整轮，页面无结果可用，自动玩可能停在“忙碌/分析”状态。
4. 深度/概率截断先于终局判定，死亡状态可能得到普通的良好启发值。
5. 多个相同最大块只以扫描到的第一个位置计算角落奖励，造成旋转偏置。
6. 位移运算处理更大数字、五位行表处理溢出合并会损坏表示。

新版本先以共同 d2 建立结果，再在原有 JS 兼容预算内渐进加深；若 d2 仍超时则全部退回 d1。同时延迟创建回退表、在每轮初始化后清缓存、统一根方向评分方式、直接计算目标深度、超时后全部根共同回到浅层、先判定终局，并修复并列最大块位置及大数字表示。普通 WASM 核心字节保持不变。

## 速度优化与边界

- 健康线程池可复用；重复分析同一规范化棋盘/强度可复用最近完整结果。
- 正常 WASM 路径不再为 4 个 Worker 提前分配共 32 MiB 的 JS 回退行表缓冲区。
- 唯一合法动作直接返回，无须等待引擎冷启动。
- 棋盘复用 16 个 DOM 节点；极速渲染限制频率；消除逐棋子的 computed-style 读取与同步布局强制刷新。
- 风险筛查的合法移动计数使用直接扫描，不再为每个方向创建棋盘数组，触发语义保持一致。
- UI 状态文字和指标节流，评分条取消每步 CSS 过渡。

未重写的 WASM 仍保留历史文档中说明的启发式阶段跳变与内部对称性限制。此升级改善的是调度隔离、可用性与兼容路径的正确性；总体达成率是否提高，必须用更大样本验证。

审查纠正：早期怀疑首次 `LEGACY.clearTT()` 会因 TT 尚未建立而立即报错，但复现表明普通调用只递增 epoch，不访问空表。该项已撤回，不计为原版已确认缺陷。

## 完整对局发现的候选版回退与修正

初始 V9.2 候选在 20 组配对中，轻快 ≥4096 为 14/20，原版为 20/20；均分也下降。没有把这个候选当作棋力升级通过。调度复查发现各根派发时重新计算预算可导致同轮配额不同（毫秒取整放大差异），且消息等待仍消耗预算。最终修正为同轮共享配额、按 Worker 搜索历时的最长通道逐轮计账。新增回归约束此行为，重新执行独立对比。初始全部数据保留在 `v9.2-initial-results.json`，最终数据与局限见 Benchmark 报告。
