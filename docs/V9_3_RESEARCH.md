# V9.3 研究与设计

## 目标和范围

用户要求继续升级，可加入自行设计的算法技术，但需仔细研究并保持质量、速度。上传项目为 V9.2。本次采取能核验等价性的局部算法优化；没有以“原创”之名替换已经有历史反例的主搜索策略。

项目的普通 WASM 与 Survival WASM 均保留原始字节。变化落在 32768+ 或 WASM 不可用时启用的 JavaScript 兼容搜索。正常模式的质量底线、风险复核、预算、采样、UI 与 Mac 启动机制延续 V9.2。

以下为本次实际查阅的原始实现/论文；查询日期为 2026-09-20。这里只借鉴方法原理，没有复制外部实现或引入运行时依赖。

## 自行设计的组合：完整棋盘叶值复用 + 可逆出生遍历

这是针对本项目写出的实现组合，基础原理属于已知的记忆化与回溯方法；不主张学术首创、专利新颖性或新的最强 2048 算法。

### 1. 只复用与搜索路径无关的叶值

原函数在每次启发评估时计算平滑度、单调性、八个蛇形方向和大块位置等奖励；相同叶棋盘会重复出现。缓存函数 E(b)，其中 b 是 16 个 rank。

16 个 8-bit rank 无损打包为四个 Uint32，完整 128 位比较后才命中。散列只选择 8192 个槽位之一，碰撞会覆盖或未命中，不会返回其他棋盘的评分。无需 BigInt 或字符串键。rank 31、32 等不会在键中截断成五位数。

缓存保存原评价函数的 Float64 输出，不重排任何求和。该评价函数没有读取 CFG，所以跨根、跨轮或模式变化复用叶值仍然成立。奖励 gain 在调用者中按原位置相加，不能进入叶值缓存。

边界：缓存不包含 maxNode 的终局判定，故先判断终局再进行深度/概率截断的顺序仍被保留。全空棋盘等输入保留原 maxNode 行为，本次不改变游戏规则。

### 2. 可逆地遍历随机出生

原 chanceNode 对每个空格复制两次棋盘，然后分别模拟 2 和 4。新版在自己拥有的工作棋盘上先放 rank 1，递归返回后改为 rank 2，最后在 finally 中清回 0。子 maxNode 的每次移动会创建独立结果棋盘，不保留父工作棋盘引用。

无空格的递归会降低 depth；有出生的递归进入独立移动结果。状态只有同步嵌套访问，因此可以安全回溯。即使超时抛出，所有经过的出生格也会逐层恢复。

出生顺序仍为原空格顺序，每格先 2 后 4；表达式仍为 `sum += .9*s2 + .1*s4`。概率除数、采样集合与搜索 TT 的访问顺序均不改变。

### 3. 减少行移动临时对象

moveBoard 内部直接取缓存行的打包结果及合并奖励，省去每一行返回的二元素数组。公开的 rowMove 测试入口继续保留。最大节点按既有方向顺序移动、搜索，避免预先保留四套移动结果。

### 4. 超时与节点指标

每次 evaluate 调用仍先增加 NODES，并在原位置检查 deadline；缓存命中也一样。这样 fixed-depth 的逻辑节点数可与 V9.2 一一比较，deadline 的检查密度也不变。

`leafHits` 与 `leafMisses` 随 JS exact 结果返回；两者之和是完成/已执行的评价访问数。报告中的 nodes/s 是逻辑吞吐，不能冒称实际重新执行评价器次数。旧 WASM 未导出 TT 命中率，因此该指标标为不可用，不用叶缓存命中率替代。

## 等价性论证

对于任何完成的固定深度请求：

- 叶缓存命中验证了全部 rank，返回值就是原 E(b)；未命中执行原 E(b)。
- 每个出生递归看到的棋盘与原 slice 版本逐元素相同，返回后恢复父状态。
- 方向顺序、概率、奖励和运算顺序相同，因此搜索 TT 的调用次序保持。
- 归纳到根，评分和逻辑节点数一致。直接浮点相等断言比容差比较更严格。

这不等于主搜索已成为数学上的 exact Expectimax：历史采样与近似 TT 仍存在。“精确”特指新叶缓存和新旧固定参数计算等价。

## 成本、取舍与限制

固定数组开销：8192 × (4×4 + 8 + 1) = 204800 字节，即每个 JS 计算线程 200 KiB。只在 getLegacy 首次创建兼容引擎时分配，普通 WASM 路径不支付该内存成本。已有行表与搜索 TT 不扩大。

未命中的叶需要额外完整键比较；没有在理论上假定它必然更快，而是用真实工作线程 A/B 验证整体收益。超大、稀疏或特殊分布棋盘仍可能有不同命中率，报告不能覆盖所有输入和设备。

墙钟预算下，运行加快可完成更多搜索层；项目已知深度振荡意味着不能据此保证任意单局得分单调增加。保留 Verifier 等护栏，并同时报告固定深度等价、整步延迟与小样本整局结果，不用小样本宣称统计显著的胜率提升。

当前环境没有可用的浏览器可执行文件，也没有 macOS。已使用真实 Node Worker 与状态测试；未进行 Safari/Chrome 真实点击、截图或 Mac 启停验收。与 V9.2 相同的老 WASM 评价器阶段跳变、内部对称性问题和大数字表示边界不在本版修复范围内。
