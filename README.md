# 2048 AI

单文件、离线可玩的 2048，内置自动求解 AI。普通局面走 WebAssembly 主核，32768+ 大数字自动切到 JavaScript 兼容搜索，双引擎由 Web Worker 调度。

**在线试玩：** https://yyh-0428.github.io/ai2048/

零依赖、无账号、不联网。整个游戏就是一个 HTML 文件。

---

## 快速开始

| 方式 | 操作 |
|---|---|
| 在线 | 打开上方试玩链接 |
| macOS | 双击 `启动 2048 AI.command`（首次受阻时右键「打开」） |
| 任意平台 | 直接用浏览器打开 `2048-ai.html` |

`停止本地服务.command` 只停止本文件夹启动的服务。本地服务固定使用 20480 端口，保证每次启动都是同一个 origin，分数和设置才能留存。

## 操作

| 按键 | 作用 |
|---|---|
| 方向键 / WASD / 滑动棋盘 | 移动 |
| 空格 | 开始或暂停自动玩 |
| Esc | 暂停 |
| H | 提示一步 |
| M | 声音开关 |

- 撤销：当前页面会话最多保留最近 60 步；自动玩暂停后可撤销。
- 刷新可恢复棋盘、分数和步数，但不恢复撤销历史。
- 合成 2048 后可以继续冲更大的数字。
- 本局进度、最高分、强度、间隔和声音设置保存在浏览器本地；清理浏览器数据会清除记录。

## 三档强度

| 强度 | 定位 |
|---|---|
| 轻快 | 优先速度 |
| 深入 | 均衡思考 |
| 极致 | 更多残局复核 |

走棋间隔只改变观看节奏，不改变搜索预算，`0 ms` 取消额外等待。

## AI 引擎

- **WASM 主核** — 普通局面的默认搜索引擎，固定深度下逐位确定。
- **Survival 引擎** — 残局生存评估，与主核共享同一套规则。
- **JS 兼容引擎** — 32768+ 大数字或 WASM 不可用时接管，V9.3 起加入 8192 槽、128 位完整棋盘键的精确叶值缓存。
- **调度线程** — 1 个调度 Worker 派发任务给多个计算 Worker，支持限时预算与任务取消。
- **Verifier** — 对高风险落子做复核，降低明显失着。
- **背景动画与无障碍** — 页面切到后台时降频，交互保持键盘可达。

## V9.3 升级要点

针对 32768+ 或 WASM 不可用时的 JavaScript 兼容搜索：

- 完整棋盘叶值缓存：比较全部 128 位棋盘后才复用原始评分，避免散列碰撞误判。
- 可逆出生遍历：减少 2/4 分支的棋盘复制，超时退出时也恢复状态。
- 行移动直接查表与按序搜索：减少临时数组和同时存活的移动棋盘。

这是为本项目自行编写的等价优化组合；不宣称记忆化/回溯原理为学术首创。普通 WASM、Survival、三档配置和 Verifier 维持原样。

## 验证结果

- 202 个局面，普通与兼容路径各 739 个根方向，重复三轮：共 **4434 次新旧配对，固定深度的评分和逻辑节点数全部相同**。
- 大数字兼容路径平均耗时降低约 **36.31%**（P95 约降低 35.36%），逻辑吞吐为原来的 1.570 倍。
- 普通 WASM 字节不变；普通整步响应的三档平均差异均在约 1% 以内。
- 回归测试 24/24 通过（规则、WASM、Survival、Verifier、轮次预算、取消、存档、DOM 状态）。

| 引擎 | 版本 | 平均 ms | P50 ms | P95 ms |
|---|---|---:|---:|---:|
| WASM normal | 9.2 | 1.006 | 1.007 | 1.667 |
| WASM normal | 9.3 | 1.017 | 1.014 | 1.672 |
| JS 大数字兼容 | 9.2 | 1.418 | 1.495 | 2.212 |
| JS 大数字兼容 | 9.3 | **0.903** | **0.946** | **1.429** |

这些是 Node 真实 Worker 实测，不能保证所有设备恒定加速或每一局得分更高。固定深度等价不等于时间预算下必走同一方向；运行更快可能完成更多层搜索。普通主核未修改，不能把普通整局的小样本得分变化归因于棋力升级。详细数据、对局原始结果与证据限制见 `docs/V9_3_BENCHMARK_RESULTS.md`。

## 工程结构

```
src/                    源码
  2048-ai.html          构建产物：单文件应用（本地用）
  index.html            构建产物：同一份内容（Pages 入口）
  page.html             页面骨架，含 WORKER_SOURCE / UI_SOURCE 注入点
  rules.js              规则与局面表示
  worker.js             搜索引擎（WASM 主核 + JS 兼容路径）
  coordinator.js        调度线程
  ui.js                 界面与输入
tools/build.mjs         零依赖构建：把源码内联成一个 HTML
tests/                  回归、配对基准、对局冒烟
docs/                   架构、决策日志、各版验证报告
docs/history/           旧版本存档
survival_v9_1.c/.wasm   Survival 引擎源码与编译产物
build-survival-wasm.sh  重新编译 Survival WASM
```

## 开发与复现

仅开发与测试需要 Node（本次使用 Node 24）：

```sh
npm run build            # 构建 2048-ai.html + index.html
npm test                 # 回归测试
npm run benchmark:fixed  # 固定深度配对
npm run benchmark:latency
npm run benchmark:games -- 6
npm run report
```

完整复现：

```sh
npm run build
npm test > docs/v9.3-regression.log 2>&1
npm run benchmark
npm run report
```

请顺序执行计时实验，避免竞争 CPU。扩大样本可用 `node tests/benchmark-v9.3.cjs games 50`；`BENCH_OUTPUT` 环境变量可指定新的结果 JSON，报告默认读取 `docs/v9.3-results.json`。

## 限制

- 每个启用兼容引擎的计算线程增加 200 KiB 叶缓存，四线程共 800 KiB；正常 WASM 使用不分配该缓存。
- 老 WASM 的评价器阶段跳变与内部对称性问题仍在，不宣称已经修复。
- 后台限速、CPU 竞争、设备温度仍可能影响速度。
- 性能基准在 Node / linux / x64 环境测得，不是 Safari/Chrome 实机验收。
